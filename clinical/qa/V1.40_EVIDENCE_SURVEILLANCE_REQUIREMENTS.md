# Automated Evidence Surveillance

Status: required safety infrastructure for v1.40.

## Purpose
Continuously detect clinically relevant changes without automatically changing production clinical recommendations.

## Cadence
- Weekly scheduled surveillance of configured guideline and evidence sources.
- Separate urgent pharmacovigilance/safety-alert path for critical recalls, contraindications, restrictions, and regulator safety communications.

## Mandatory workflow
source discovery -> provenance capture -> deduplication -> relevance triage -> comparison with current evidence registry -> affected-module mapping -> proposed change -> human clinical review -> Clinical QA -> explicit approval -> merge/release.

No discovered publication, guideline, alert, model output, or generated proposal may directly modify an active clinical recommendation.

## Source policy
Prefer primary authoritative sources: DGS Portugal, EMA, INFARMED, European Commission/ECDC where applicable, WHO, ERC, ESC, AHA/ACC, NICE, Surviving Sepsis Campaign, and relevant specialty/pediatric societies. Add sources through reviewed configuration rather than hard-coding clinical conclusions.

## Required record for each finding
- source organization and canonical URL/identifier
- title/version/publication or update date
- retrieval timestamp
- affected clinical domain/module(s)
- current repository evidence version
- change classification: no-change | editorial | potentially-practice-changing | urgent-safety
- concise diff/rationale
- reviewer status and reviewer identity
- QA status
- final disposition and commit/release reference

## Fail-closed rules
- Network/source/parser failure is reported; it is never interpreted as "no new evidence".
- Unverifiable provenance is quarantined.
- Conflicting guidance is surfaced for human adjudication.
- A proposed update remains non-production until explicit human approval and QA.
- No automatic yellow -> green promotion.
- Never ingest patient data into this pipeline.

## Implementation requirements
1. Machine-readable source registry with source owner, endpoint/feed/page, domains, cadence, priority, parser strategy, and last successful check.
2. Idempotent surveillance runner with durable checkpointing and deduplication.
3. Evidence diff against clinical/references/evidence-registry.json.
4. Module-impact mapper.
5. Structured proposal artifact; no direct mutation of clinical modules.
6. Audit log that contains no PHI.
7. CI workflow scheduled weekly plus manually dispatchable.
8. Urgent-safety watcher separated from the weekly evidence review. Its polling cadence must respect source capabilities and rate limits.
9. Tests for source failure, malformed/changed pages, duplicates, conflicting evidence, stale checks, provenance loss, and attempted automatic clinical mutation.
10. Dashboard/report showing last successful check, failures, pending reviews, urgent alerts, and stale sources.

## Release gate
A clinical change generated from surveillance requires:
1. traceable primary source;
2. clinician review;
3. documented change rationale;
4. relevant regression/boundary tests;
5. Clinical QA success;
6. explicit approval;
7. normal versioned merge/release process.

This document defines the invariant. Provider/source-specific automation is implemented only after validating each source's lawful and technically stable retrieval mechanism.
