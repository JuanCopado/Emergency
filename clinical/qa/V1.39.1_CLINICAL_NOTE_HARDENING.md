# v1.39.1 — Clinical note diagnostic support hardening

Base: `v1.39-clinical-note-diagnostic-support`  
Working branch: `v1.39.1-clinical-note-hardening`  
Status: YELLOW / draft / human review required.

## Scope

Focused safety and usability hardening of the clinician-facing diagnostic note workspace.
No clinical module is promoted to GREEN and `main` is not modified.

## Changes

1. **Stale-analysis export gate**
   - Any edit after a diagnostic analysis marks the analysis stale.
   - Export remains blocked until the treating clinician explicitly acknowledges that the diagnostic support is stale.
   - The acknowledgement is reset by subsequent edits.

2. **Must-not-miss first**
   - Critical alternative diagnoses are displayed before the routine likely/differential lists.
   - Must-not-miss cards receive a stronger visual warning.

3. **Evidence symmetry**
   - Diagnostic cards now display evidence for, evidence against and missing discriminating data.
   - This reduces one-sided anchoring on the leading diagnosis.

4. **Problem representation and limitations**
   - The diagnostic workspace surfaces the engine's problem representation.
   - Explicit limitations are displayed as a separate warning block.

5. **Allergy safety**
   - An empty allergy field is explicitly treated as “not recorded”, not “no known allergies”.
   - The plan view warns when allergy status is absent.

6. **Structured medication-safety context**
   - Adds weight, eGFR, creatinine, hepatic function, pregnancy, anticoagulation/agent and explicit allergy status.
   - The values are serialized through the existing payload shape as a tagged medication-safety context rather than silently changing the API schema.
   - Medication suggestions display a caution when the minimum safety context is incomplete.

7. **Append-only session audit trail**
   - MCDT creation/edit/accept/reject, diagnostic analysis and export events are appended with timestamp and target.
   - The last audit events are included in the exported note privacy/audit metadata.
   - Export revisions are numbered in clinician-validation metadata.

8. **Critical-diagnosis export gate**
   - Must-not-miss diagnoses or RED_FLAG signals require explicit clinician acknowledgement before export.
   - Editing the note resets this acknowledgement.

9. **Regression coverage**
   - UI tests cover evidence-against display, must-not-miss visibility, stale-export blocking, allergy-status warning, medication safety context, audit trail and the critical-diagnosis export gate.

## Remaining high-value improvements

- Persist the audit trail server-side with tamper-evident signing; the current UI trail is append-only only within the active session.
- Replace tagged safety-context serialization with a versioned backend schema after compatibility review.
- Add cryptographic/signed clinician attestation for every export.
- Structured medication reconciliation with dose/schedule parsing and discrepancy state.
- Link each diagnostic candidate to current module version/evidence timestamp.
- Validate DOCX/PDF export metadata against privacy policy.
- Add local Portugal information-governance review before any production use.

## Validation boundary

Automated UI or Clinical QA is not prospective clinical validation. The workspace remains YELLOW until clinical, pharmacy, legal/privacy and information-governance review is completed.
