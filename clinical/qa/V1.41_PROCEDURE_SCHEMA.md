# V1.41 — Schema maestro de procedimientos

## Objetivo
Definir una única estructura canónica, validable y reutilizable para todas las técnicas y procedimientos del proyecto Emergency.

## Archivos
- `clinical/schemas/procedure-v1.41.schema.json`: JSON Schema canónico.
- `clinical/templates/procedure-template-v1.41.json`: plantilla vacía editable.

## Principios
1. Un único ID canónico por procedimiento.
2. Separar contenido clínico, farmacología, POCUS, documentación y QA.
3. No duplicar dosis: usar `pharmacology_links`.
4. Mantener `status=YELLOW` y `human_review_required=true` hasta revisión humana.
5. La fase visual permanece pausada; `visual_qa=paused` es el valor por defecto.
6. Cada procedimiento debe tener STOP points, confirmación, rescate y documentación.
7. Las fuentes deben quedar explícitas por procedimiento.

## Correspondencia con la ficha textual
- objetivo → `objective`
- indicaciones → `indications`
- contraindicaciones/precauciones → `contraindications_precautions`
- material → `equipment`
- anatomía → `anatomy`
- preparación → `preparation`
- paso a paso → `steps`
- confirmación → `confirmation`
- STOP → `stop_points`
- complicaciones → `complications`
- fallo/rescate → `rescue`
- cuidados posteriores → `aftercare`
- documentación → `documentation`
- perlas → `pearls`
- adaptaciones → `special_adaptations`
- POCUS → `pocus`
- farmacología → `pharmacology_links`
- fuentes → `sources`
- QA → `qa`

## Uso previsto
Este schema permite posteriormente:
- renderizar la ficha rápida y completa de la app;
- generar formularios;
- detectar campos incompletos;
- construir briefs visuales consistentes;
- validar estructura automáticamente;
- exportar contenido a JSON/API sin reescribir la clínica.
