# v1.40 Evidence Surveillance — Deployment Boundary

## Verified GitHub constraint
GitHub Actions `schedule` and `workflow_dispatch` require the workflow file on the repository default branch. The clinical invariant for this project is that `main` is not modified by this workstream.

Therefore the scheduled workflows stored only on `v1.40-evidence-surveillance` are **not an operational scheduler**. They remain executable specifications/QA assets.

## Production-safe deployment model
Use an external scheduler with read-only repository credentials. At each tick it must:

1. Check out the immutable approved surveillance revision (or an explicitly approved release tag), never floating `main`.
2. Run:
   - weekly: `python clinical/scripts/evidence_surveillance.py --cadence weekly ...`
   - urgent: `python clinical/scripts/evidence_surveillance.py --cadence urgent ...` followed by `urgent_safety_triage.py`.
3. Persist only surveillance state/reports outside the clinical source tree.
4. Never commit, push, merge, edit clinical modules, or promote evidence status.
5. Route detected changes to the human review queue.
6. Require clinician review; medication safety changes additionally require pharmacist review.
7. Require regression + Clinical QA before any separately authorized clinical code change.

## Cadence
- Weekly evidence discovery: once weekly.
- Urgent medication-safety polling: every 6 hours. This is polling, not real-time pharmacovigilance.

## Required scheduler controls
- Read-only GitHub token / deploy credential.
- Pinned approved commit or signed release tag.
- Concurrency lock.
- Durable state with schema validation.
- Failure alerting and stale-run alerting.
- Audit retention.
- No PHI.
- Network allowlist for approved source hosts.
- Cross-host redirects rejected.
