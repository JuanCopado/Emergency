# PM03: correcciones de la auditoría PM02 (copia aislada)

Base conservada: PR25, commit `fba27dcc898b6b42893f46823efd3f8385a06432`, árbol `ca602f9d102f996f65bdf5bc27fef8f1d4ebf548`.
Esta propuesta solo modifica infraestructura de seguridad y pruebas. No integra R2/E1 ni cambia contenido, cálculos, dosis, protocolos o validación clínica.

| Hallazgo | Control de esta propuesta |
|---|---|
| Rollup incluye copias no inventariadas | Perfiles de bytes originales y corregidos para cuatro archivos / seis analizadores de Rollup 4.63.5, además de diez archivos de las cinco copias de picomatch. Comprobación obligatoria antes de ejecutar herramientas y fuzz por API pública de Rollup. |
| Rechazo de patrones legítimos | Se admiten repeticiones de literales, clases simples y alternativas literales sin prefijos ambiguos. Ejemplos verificados: `a+(b)`, `*([0-9]).txt`, `+([a-z]).js`, `x/*(a)/y`. |
| Regex cruda y comodines polinómicos | Los dos accesos del parser fuerzan `regex:false`; se rechazan inyecciones mediante `prepend`/`expandRange`. La ejecución estándar del RegExp verifica longitud y presupuesto conservador antes de ejecutar. |
| Pruebas sobre node_modules activo / escrituras parciales | Pruebas mutantes únicamente en fixtures privados, con hashes de las dependencias activas antes/después. Reemplazos individuales por archivo temporal, fsync y rename. Bloqueo exclusivo y diario: una operación interrumpida bloquea el arranque hasta completar la aplicación. Revertir solo se permite en fixtures. |
| Ciclo de instalación ambiguo | Modos explícitos `project-hook` y `explicit-apply`; modo `automatic-fixture` comprueba un ciclo automático npm real en un paquete sintético sin dependencias que ejecuta el controlador exacto del proyecto. No equivale a habilitar scripts de todas las dependencias en Windows CI. App UI conserva su instalación automática completa en Linux. |
| Cobertura V8 sin procedencia | Ejecución nueva controlada, directorio único, nonce, hashes de fuentes antes/después y de capturas; solo se integran contadores reales de ambas fuentes de protección. No se añaden exclusiones ni se cambian umbrales. |
| Severity ausente en Trivy | Falta de severidad, valor no enumerado o tipo incorrecto produce ERROR y salida 2. UNKNOWN explícito conserva su tratamiento anterior. HIGH/CRITICAL y cualquier secreto continúan bloqueando. |
| Acciones de App UI sin SHA | SHA fijado y checkout sin credenciales persistidas. |

## Alcance y límites

- Es una mitigación local y temporal; no es una corrección oficial de picomatch ni de Rollup.
- Rollup 4.68.7 oficial también reproduce el caso en la auditoría precedente. Actualizar solo su número no resuelve el comportamiento; esta propuesta mantiene el lock revisado de 4.63.5 y protege sus copias incorporadas.
- GitHub retiró GHSA-fc5q-39xc-vjpf el 18/11/2026 a las 15:38:56 UTC. npm sigue publicando picomatch 4.0.7 y Rollup 4.68.7 como latest al consultar esta propuesta. La retirada es un cambio de clasificación, no una prueba de ausencia del comportamiento. Se conservan los anteriores resultados Trivy con dos HIGH y se repite el escaneo sin excepciones.
- La protección restringe ciertos patrones válidos, opciones avanzadas, longitud (patrón 1024 / entrada 8192) y cargas estimadas. No garantiza equivalencia de todo el lenguaje glob ni un límite matemático para todas las expresiones.
- El presupuesto de trabajo es heurístico. El fuzz es reproducible y acotado, nunca exhaustivo. Entradas desconocidas no deben controlar globs de herramientas de desarrollo.
- No se ha demostrado un vector remoto desde la PWA clínica. La condición comprobada es permitir un patrón adversario en APIs de herramientas Node/Rollup.
- `RegExp.prototype.exec.call`, recompilar `.source`, estados de parser fabricados y `toRegex` con regex arbitraria son JavaScript de confianza fuera del contrato protegido. Esto no aísla código malicioso.
- El detector adicional reconoce firmas de parser conocidas; no demuestra ausencia de cualquier copia minificada u ofuscada. El lock exacto y hashes de todos los archivos identificados impiden aceptar silenciosamente cambios en los componentes revisados.
- Los reemplazos son atómicos por archivo, no una transacción atómica de todo node_modules. El diario permite detectar y completar interrupciones de proceso; no certifica recuperación ante pérdida física de energía. Deben cerrarse/reiniciarse procesos de herramientas que hayan cargado dependencias antes de aplicar.
- El fuzz limita procesos, memoria y tiempo; no constituye un aislamiento de archivos o red. Solo ejecuta dependencias revisadas con datos sintéticos, sin PHI ni credenciales.
- No se elimina la mitigación por un cambio de base de datos. Su retirada requiere revisión de la frontera de confianza, versiones/código efectivos, regresiones de las copias incorporadas, instalaciones limpias, CI y un Trivy actual sin excepciones. Si Trivy sigue detectando HIGH, permanece bloqueado.

## Comandos de comprobación

Desde `app`: `npm ci --ignore-scripts --no-audit --no-fund`, `npm run security:picomatch:apply`, `npm run security:picomatch:check`, `npm run security:picomatch:test`, `npm run lint`, `npm test`, `npm run build`, `npm run test:coverage`, `node scripts/check-picomatch-coverage.mjs --run`.
Fuzz: `python ../security/tests/picomatch_fuzz.py --app . --out <ruta fuera del candidato>/fuzz.json`.
Informes: `python -B -m unittest discover -s security/tests -p 'test_*.py'` desde la raíz.
CI conserva los cuatro manifiestos obligatorios y la política completa de Trivy.
